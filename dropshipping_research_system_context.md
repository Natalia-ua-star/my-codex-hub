# Dropshipping Research System — повний контекст системи

> Автоматизована система пошуку й перевірки товарів для дропшипінгу.
> Цільові ринки: **US, CA, GB, AU, NZ**.
> Головний результат — повне доказове досьє кожного товару: попит, країни, постачальники,
> landed cost, конкуренти, ціни, офери, реклама, соцмережі, ризики, можливості та фінальне
> `decision` із `next_action`.

---

## 1. Мета системи

Система проводить кожен потенційний товар через єдиний конвеєр перевірок і накопичує
докази в структурованих таблицях. Рішення про запуск ухвалюється не інтуїтивно, а на
основі зібраного досьє: попит → постачання → конкуренція → реклама → оцінка → рішення.

## 2. Конвеєр (8 кроків)

1. **Знайти потенційний товар** — ідея потрапляє в `01_Inbox` з будь-якого джерела
   (spy-платформи, соцмережі, маркетплейси, ручний ввід).
2. **Перевірити органічний попит і Google Shopping** — ключові слова в `06_Keywords`,
   сигнали попиту по країнах у `03_Market_Signals`.
3. **Створити товар з одним стабільним `product_id`** — канонічний запис у `02_Products`;
   усі подальші дані в усіх таблицях посилаються на цей `product_id`.
4. **Знайти постачальників і конкурентів** — постачальники та landed cost у `04_Suppliers`,
   конкуренти, їхні ціни й офери в `05_Competitors`.
5. **Перевірити рекламу саме товару** — рекламна гілка «Product Ads» у `09_Ads`:
   чи рекламується цей конкретний товар, ким, де і як довго.
6. **Проаналізувати всю рекламу конкурентів** — окрема рекламна гілка «Competitor Ads»
   у `09_Ads`: що рекламують конкуренти загалом, як довго крутяться оголошення,
   формати, офери, хуки й креативи.
7. **Знайти продуктові публікації в соцмережах конкурентів** — знахідки в `10_Discoveries`:
   органічні пости конкурентів про товари, залучення, коментарі, реакція аудиторії.
8. **Розрахувати оцінки та фінальне рішення** — зведення в `07_Shortlist`:
   скоринг за напрямами, ризики, можливості, `decision` і `next_action`.

## 3. Таблиці системи (11 таблиць)

Порядок нижче відповідає ходу роботи конвеєра, а не номерам.

| Таблиця | Призначення |
|---|---|
| `00_Niches` | Каталог ніш: назва, статус, пріоритет, обмеження, нотатки. Кожен товар належить до ніші. |
| `01_Inbox` | Вхідні ідеї-кандидати до валідації: сирі знахідки з усіх джерел, статус первинного відбору. |
| `02_Products` | Канонічний реєстр товарів. Тут народжується стабільний `product_id`. Один товар — один рядок. |
| `06_Keywords` | Ключові слова товару для перевірки органічного попиту та Google Shopping (по країнах). |
| `03_Market_Signals` | Сигнали ринку по країнах: органічний попит, тренди, Google Shopping, сезонність. |
| `09_Ads` | Уся реклама: обидві гілки — реклама самого товару та реклама конкурентів (розділені полем гілки). |
| `10_Discoveries` | Продуктові публікації в соцмережах конкурентів: пости, формати, залучення. |
| `04_Suppliers` | Постачальники товару: ціна закупки, доставка, строки, landed cost по країнах. |
| `05_Competitors` | Конкуренти: магазини, ціни, офери, позиціювання, сильні/слабкі сторони. |
| `07_Shortlist` | Зведене досьє та рішення: оцінки за напрямами, ризики, можливості, `decision`, `next_action`. |
| `99_Lists` | Службові довідники: статуси, країни, джерела, формати реклами, типи рішень тощо. |

## 4. Правила ID

- **`product_id` — єдиний і стабільний.** Створюється один раз у `02_Products` і ніколи
  не змінюється, навіть якщо змінюється назва, ніша чи постачальник товару.
- Усі дочірні записи (`06_Keywords`, `03_Market_Signals`, `09_Ads`, `10_Discoveries`,
  `04_Suppliers`, `05_Competitors`, `07_Shortlist`) обов'язково містять `product_id`
  того товару, якого стосуються.
- Записи в `01_Inbox` до створення товару мають власний inbox-ідентифікатор; після
  схвалення кандидата створюється запис у `02_Products`, і inbox-рядок отримує
  посилання на новий `product_id`.
- Дочірні таблиці можуть мати власні локальні ID рядків (id ключового слова, id
  оголошення, id постачальника), але зв'язування між таблицями йде тільки через
  `product_id`.
- Кожен рядок дослідження містить дату знахідки/оновлення (`search_date`).

## 5. Розділення рекламних гілок

У `09_Ads` живуть дві незалежні гілки, які не можна змішувати:

1. **Product Ads (крок 5)** — реклама *саме цього товару*: хто його рекламує,
   на яких платформах, у яких країнах, як довго активні оголошення. Відповідає на
   питання «чи вже продають цей товар через рекламу і наскільки агресивно».
2. **Competitor Ads (крок 6)** — *вся* реклама конкурентів, незалежно від товару:
   що вони рекламують, тривалість відкрутки, формати (відео/статика/каруселі),
   офери, хуки, креативи. Відповідає на питання «як працює рекламна машина
   конкурента і що в нього спрацьовує».

Кожен рядок у `09_Ads` позначений гілкою, щоб аналітика по товару не змішувалася
з аналітикою по конкуренту.

## 6. Оцінки та фінальне рішення

`07_Shortlist` зводить усе досьє в оцінки за напрямами:

- попит (органіка, Shopping, тренди по країнах);
- постачання (доступність, landed cost, строки);
- конкуренція (кількість, ціни, сила оферів);
- реклама (насиченість, тривалість відкруток, якість креативів конкурентів);
- соцмережі (органічна активність і реакція аудиторії).

На основі оцінок фіксуються **ризики**, **можливості** та фінальне поле
`decision` (наприклад: запускати / тестувати / відкласти / відхилити) разом із
конкретним `next_action` — що саме робити далі з цим товаром.

## 7. Поточний стан роботи

- Структура з 11 таблиць визначена й зафіксована (розділ 3).
- Правила ID та розділення рекламних гілок узгоджені (розділи 4–5).
- Конвеєр із 8 кроків описаний як цільовий процес (розділ 2).
- Наступні кроки: наповнення довідників `99_Lists`, автоматизація кроків конвеєра
  та прогін перших товарів через повний цикл до `decision` у `07_Shortlist`.
