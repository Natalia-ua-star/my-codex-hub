# Airtable Automation

## Що робить цей скіл

Проектує структуру баз Airtable, налаштовує автоматизації, views, формули, rollup/lookup поля та інтеграції з Make.com, Zapier, Slack, Gmail та іншими сервісами.

## Тригери (коли активується)

- "Airtable база", "налаштуй Airtable", "automation в Airtable"
- "зроби CRM в Airtable", "база замовлень", "трекер проектів"
- "підключи Airtable до...", "формула в Airtable"
- "Airtable view", "gallery/kanban/calendar у Airtable"

## Вхідні дані (що уточнити перед роботою)

1. **Мета**: CRM, трекер задач, каталог продуктів, інвентар?
2. **Сутності**: які об'єкти та їх зв'язки (таблиці та відносини)?
3. **Автоматизація**: що має запускатись і коли (тригер + дія)?
4. **Інтеграції**: з якими зовнішніми сервісами потрібен зв'язок?
5. **Права доступу**: скільки користувачів, які ролі?

## Алгоритм роботи

### Крок 1 — Проектування структури бази
- Визначити таблиці (одна сутність = одна таблиця).
- Налаштувати зв'язки: "Link to another record" між таблицями.
- Обрати типи полів: Single line, Long text, Number, Date, Checkbox, Select, Attachment, Formula, Rollup, Lookup.

### Крок 2 — Налаштування полів-обчислень
Формули Airtable (синтаксис схожий на Excel):
- `IF({Статус}="Виконано", "✅", "⏳")` — умовне форматування.
- `DATETIME_FORMAT({Дата}, "DD.MM.YYYY")` — формат дати.
- `CONCATENATE({Ім'я}, " ", {Прізвище})` — об'єднання тексту.
- Rollup: SUM, COUNT, AVERAGE значень із пов'язаної таблиці.
- Lookup: підтягування поля із пов'язаного запису.

### Крок 3 — Створення Views
- **Grid** — стандартна таблиця, з фільтрами та сортуванням.
- **Gallery** — карточки (зручно для продуктів з фото).
- **Kanban** — за полем Single/Multiple Select (статус задачі).
- **Calendar** — за полем Date (розклад, дедлайни).
- **Gantt** — хронологія проектів (платно).
- Групування, фільтри та сортування зберігаються для кожного view.

### Крок 4 — Automations (вбудовані)
Налаштувати через вкладку "Automations":
1. **Тригер**: "When record created/updated", "At scheduled time", "When form submitted".
2. **Умова** (опційно): перевірити значення поля перед дією.
3. **Дія**: Send email, Create/Update record, Run script, Send Slack message, HTTP request (webhook).

Приклад: при зміні статусу на "Виконано" — надіслати email клієнту та оновити дату завершення.

### Крок 5 — Інтеграція з Make/Zapier
- Make: модуль "Airtable → Watch Records" або "Create/Update Record".
- Zapier: тригер "New Record in View", дія "Create Record".
- API: `https://api.airtable.com/v0/{baseId}/{tableName}` — REST API з Bearer token.

### Крок 6 — Тестування
- Додати тестовий запис, перевірити що automation спрацьовує.
- Перевірити rollup/lookup на кількох пов'язаних записах.
- Протестувати webhook — надіслати POST-запит і перевірити результат.

## Формат відповіді

- Структура таблиць зі списком полів і типів.
- Готові формули у блоках коду.
- Покрокова інструкція для налаштування automations.
- Приклад API-запиту якщо потрібна інтеграція.

## Правила

- Одна сутність — одна таблиця; не зберігати різні об'єкти в одній таблиці.
- Уникати дублювання даних — використовувати Lookup замість копіювання.
- Для великих баз (>50k записів) — рекомендувати платні плани або NocoDB.
- API ключ зберігати у Make/Zapier як credentials, не передавати у відкритому вигляді.
- Попереджати про ліміти безкоштовного плану: 1200 записів/база, 2 тижні history.
