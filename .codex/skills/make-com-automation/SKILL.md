# make-com-automation

## Що робить

Проектує, будує та налагоджує сценарії Make.com (раніше Integromat). Підтримує роботу з модулями, тригерами, фільтрами, маршрутами, обробниками помилок та blueprint JSON.

## Тригери

- "зроби автоматизацію в Make"
- "Make сценарій"
- "підключи Make"
- "blueprint Make"
- "налаштуй webhook в Make"
- "Make.com інтеграція"

## Вхідні дані

- Опис завдання: що має відбуватись, коли і чому
- Перелік залучених сервісів (Shopify, Gmail, Google Sheets тощо)
- Наявні credentials або підключення
- Бажана частота запуску або тип тригера (webhook / scheduled / instant)

## Алгоритм

1. **Уточнення задачі** — з'ясувати тригер (що запускає), дані (що передається), дію (що на виході).
2. **Проектування схеми** — описати послідовність модулів: Trigger → [Filter] → Module 1 → [Router] → Module 2a / 2b.
3. **Визначення модулів** — підібрати правильні Make-модулі (Search, Watch, Create, Update, Iterator, Aggregator тощо).
4. **Blueprint JSON** — генерувати або редагувати програмно через `json.load()` + `json.dumps(separators=(",",":"))`. Ніколи не редагувати текстовим find/replace.
5. **Фільтри та маршрути** — додати умови між модулями; описати логіку кожного маршруту роутера.
6. **Обробка помилок** — рекомендувати Break / Resume / Ignore відповідно до критичності операції.
7. **Тестування** — порядок: Run once → перевірити дані кожного модуля → виправити маппінг.
8. **Документування** — стисло описати сценарій для запису в Notes або Notion.

## Правила

- `jsonStringBodyContent` у HTTP-модулях завжди подвійно-кодується: `json.dumps(json.dumps(obj, separators=(",",":"))).`
- Індексація масивів у Make починається з **1**, не з 0.
- Екрановані лапки всередині виразів `{{ }}` ламають парсер — уникати.
- Перед публікацією — тест у режимі "Run once" з реальними даними.
- Для Shopify-вебхуків використовувати instant trigger, не scheduled.
- Якщо blueprint завантажується з файлу — перевіряти версію (`"version": 2`).

## Формат виходу

```
## Схема сценарію
Trigger: [назва модуля + сервіс]
↓
Filter: [умова, якщо є]
↓
Module 1: [назва] — [опис дії]
↓
Router:
  ├─ Маршрут A: [умова] → Module 2a
  └─ Маршрут B: [умова] → Module 2b

## Налаштування модулів
| Модуль | Поле | Значення / маппінг |
|--------|------|--------------------|
| ...    | ...  | ...                |

## Важливі моменти
- [список нюансів, обмежень, рекомендацій]
```
