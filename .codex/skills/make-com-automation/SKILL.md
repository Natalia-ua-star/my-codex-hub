# Навичка: make-com-automation

## Що робить
Проєктує, будує та налагоджує сценарії автоматизації в Make.com (раніше Integromat).
Покриває весь цикл: від постановки задачі до готового blueprint-файлу або покрокової інструкції налаштування.

## Тригери (коли активується)
- "зроби автоматизацію в Make"
- "Make сценарій"
- "підключи Make"
- "blueprint Make"
- "налаштуй модуль в Make"
- "Make.com інтеграція"

## Вхідні дані (що запитати у користувача)
1. **Мета автоматизації** — що повинно відбуватись? (напр. "при новому замовленні Shopify → надіслати email")
2. **Тригер** — яка подія запускає сценарій? (Webhook, розклад, нова запис у Google Sheets тощо)
3. **Джерела та цілі** — які сервіси підключені (Shopify, Gmail, Notion, Airtable, HTTP тощо)?
4. **Наявні credentials** — чи є вже підключені акаунти в Make?
5. **Формат виводу** — blueprint JSON, покрокова інструкція або обидва?

## Алгоритм (кроки)

### Крок 1 — Аналіз задачі
- Визначити тригер (Instant / Scheduled / Manual)
- Розбити логіку на лінійні блоки: Тригер → Трансформація → Дія
- Виявити умови (фільтри, маршрути)

### Крок 2 — Архітектура сценарію
- Побудувати схему модулів: `[Trigger] → [Filter?] → [Module1] → [Router?] → [Module2..N]`
- Визначити змінні, що передаються між модулями (mapping)
- Врахувати обробку помилок: Ignore / Rollback / Commit

### Крок 3 — Blueprint JSON
- Сформувати коректний JSON відповідно до схеми Make.com
- Поле `jsonStringBodyContent` завжди подвійно кодувати через `json.dumps(obj, separators=(",", ":"))`
- Індексація масивів — 1-based (Make стандарт)
- Ніколи не використовувати текстову заміну в JSON — тільки програмну модифікацію

### Крок 4 — Валідація
- Перевірити коректність посилань між модулями (`moduleId`)
- Підтвердити наявність всіх обов'язкових полів
- Перевірити вирази `{{ }}` на синтаксичні помилки

### Крок 5 — Інструкція розгортання
- Надати покроковий опис імпорту blueprint
- Вказати які credentials потрібно підключити вручну
- Описати як протестувати сценарій (Run once)

## Формат виводу
```
## Make.com Сценарій: [Назва]

### Архітектура
[Trigger] → [Module1] → [Filter] → [Module2]

### Blueprint JSON
\`\`\`json
{ ... }
\`\`\`

### Кроки розгортання
1. ...
2. ...

### Тестування
- Очікуваний результат при тестовому запуску: ...
```

## Правила
- Не редагувати blueprint JSON через пошук/заміну тексту
- Подвійне кодування для `jsonStringBodyContent` — обов'язково
- Якщо задача складна — спочатку запитати про всі вхідні дані, потім будувати
- Запропонувати обробку помилок (error handler) для критичних модулів
- Попередити про ліміти Make (кількість операцій, розмір payload)
